## 4. احراز هویت پیشرفته (KYC)

### 4.1 سطوح KYC

```
Level 0 – Guest
  └── مشاهده محصولات

Level 1 – Basic (ثبت‌نام ساده)
  ├── خرید تا سقف روزانه مشخص
  └── کیف پول با سقف محدود

Level 2 – Verified (کارت ملی + تأیید چهره)
  ├── خرید بدون محدودیت
  ├── کیف پول با سقف بالا
  └── ثبت‌نام به عنوان فروشنده

Level 3 – Premium (مدارک تجاری کامل)
  ├── امکان دریافت لایسنس API
  ├── فروشنده ویژه
  └── گزارش‌های مالی پیشرفته
```

## 5. معماری پیشنهادی

### 5.1 Auth Service

```
auth-service/
├── controllers/
│   ├── auth.controller.ts        # login, register, logout
│   ├── oauth.controller.ts       # social login
│   ├── twofa.controller.ts       # 2FA management
│   └── session.controller.ts     # session management
├── services/
│   ├── jwt.service.ts            # token generation/validation
│   ├── otp.service.ts            # OTP generation/delivery
│   ├── kyc.service.ts            # KYC workflow
│   └── audit.service.ts          # audit logging
├── middleware/
│   ├── auth.middleware.ts        # JWT verification
│   ├── rbac.middleware.ts        # role/permission check
│   ├── ratelimit.middleware.ts   # rate limiting
│   └── captcha.middleware.ts     # CAPTCHA validation
└── models/
    ├── user.model.ts
    ├── role.model.ts
    ├── permission.model.ts
    ├── session.model.ts
    └── kyc-document.model.ts
```

### 5.2 Token Strategy

```
Access Token:  JWT، مدت ۱۵ دقیقه، در حافظه
Refresh Token: opaque، مدت ۳۰ روز، در HttpOnly Cookie
Remember Me:   Refresh Token طولانی‌تر (۹۰ روز)
```

### 5.3 جریان احراز هویت

```
Client → POST /auth/login
       ← { access_token, expires_in }
         Set-Cookie: refresh_token (HttpOnly, Secure)

Client → GET /api/protected (Authorization: Bearer <access_token>)
       ← 200 OK { data }

access_token منقضی شد:
Client → POST /auth/refresh (Cookie: refresh_token)
       ← { access_token }
```

## 6. قابلیت‌های فعال/غیرفعال

برخی از قابلیت‌های این ماژول را می‌توان از پنل ادمین فعال یا غیرفعال کرد:

| قابلیت | پیش‌فرض | نیاز به تنظیم |
|--------|---------|--------------|
| Social Login | غیرفعال | نیاز به کلیدهای API |
| 2FA اجباری | غیرفعال | قابل اجبار بر نقش‌ها |
| KYC | غیرفعال | نیاز به سرویس OCR/Face |
| SSO | غیرفعال | نیاز به تنظیم SAML/OIDC |
| Geo-blocking | غیرفعال | قابل تنظیم |
| ثبت‌نام با موبایل | فعال | – |
| تأیید ایمیل | فعال | – |
| CAPTCHA | فعال | نیاز به کلید API |

---

> **یادداشت برای توسعه‌دهنده:** این سند پایه طراحی API و دیتابیس ماژول Auth است. هر بخش باید به صورت feature flag پیاده‌سازی شود تا امکان فعال/غیرفعال‌سازی از طریق environment variables یا جدول `settings` وجود داشته باشد.
