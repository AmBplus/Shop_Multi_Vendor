## 3. مدیریت سفارشات

### 3.1 چرخه عمر سفارش

```
pending_payment    → در انتظار پرداخت (۱۵ دقیقه timeout)
paid               → پرداخت شده
processing         → در حال آماده‌سازی
ready_to_ship      → آماده ارسال
shipped            → ارسال شده
out_for_delivery   → در دست پیک
delivered          → تحویل داده شده
completed          → تکمیل شده (۷ روز بعد تحویل)
cancelled          → لغو شده
refunded           → مسترد شده
on_hold            → معلق
```

### 3.2 سفارش چند فروشنده

```
Order #ORD-2025-001
  ├── SubOrder #ORD-2025-001-A (فروشنده ۱)
  │     ├── محصول X (۲ عدد)
  │     └── وضعیت: در حال بسته‌بندی
  └── SubOrder #ORD-2025-001-B (فروشنده ۲)
        ├── محصول Y (۱ عدد)
        └── وضعیت: ارسال شده
```

> یک سفارش می‌تواند شامل محصولاتی از چند فروشنده باشد. هر زیرسفارش (Sub-order) به طور مستقل مدیریت می‌شود.

### 7.3 محاسبه امتیاز کلی

```
امتیاز کلی = میانگین موزون امتیازها

Wilson Score = (p + z²/2n ± z√(p(1-p)/n + z²/4n²)) / (1 + z²/n)
  p = نسبت نظرات مثبت
  n = تعداد کل نظرات
  z = ۱.۹۶ (۹۵٪ confidence)

→ از Wilson Score برای رتبه‌بندی محصولات استفاده می‌شود
```

## 9. معماری پیشنهادی

### 9.1 ساختار جداول

```sql
-- سفارشات
orders
  id, user_id, order_number, status
  subtotal, shipping_cost, tax, discount, total
  payment_method, payment_status, paid_at
  shipping_address_id, billing_address_id
  notes, created_at

-- زیرسفارشات (یک سفارش = چند فروشنده)
sub_orders
  id, order_id, vendor_id, status
  subtotal, shipping_cost, commission
  tracking_number, shipped_at, delivered_at

-- آیتم‌های سفارش
order_items
  id, sub_order_id, product_id, variation_id
  vendor_offer_id, quantity, unit_price, total

-- تراکنش‌های پرداخت
payment_transactions
  id, order_id, gateway, gateway_ref
  amount, status, paid_at, refunded_at

-- درخواست مرجوعی
return_requests
  id, order_item_id, reason, description
  photos JSON, status, refund_amount
  requested_at, resolved_at

-- کدهای تخفیف
coupons
  id, code, type, value, min_order
  max_uses, used_count, expires_at, is_active

-- امتیازات وفاداری
loyalty_points
  id, user_id, points, type, description
  reference_id, expires_at, created_at
```

### 9.2 API اصلی

```
# Cart
POST   /api/cart/items           # افزودن
PUT    /api/cart/items/:id       # تغییر تعداد
DELETE /api/cart/items/:id       # حذف
POST   /api/cart/coupon          # اعمال کد
GET    /api/cart/shipping-options # گزینه‌های ارسال

# Checkout
POST   /api/checkout/init        # شروع تسویه
POST   /api/checkout/payment     # پرداخت
GET    /api/checkout/verify      # تأیید پرداخت (callback)

# Orders
GET    /api/orders               # لیست سفارشات کاربر
GET    /api/orders/:id           # جزئیات
POST   /api/orders/:id/cancel    # لغو
POST   /api/orders/:id/return    # درخواست مرجوعی
GET    /api/orders/:id/track     # ردیابی

# Reviews
GET    /api/products/:id/reviews
POST   /api/products/:id/reviews
PUT    /api/reviews/:id
DELETE /api/reviews/:id
```

### 9.3 جریان پرداخت

```
POST /api/checkout/payment
  → validate cart
  → lock inventory (Redis lock)
  → create order (status: pending_payment)
  → redirect to payment gateway

GET /api/checkout/verify?ref=...
  → verify with gateway API
  → if success:
      update order status → paid
      release inventory lock
      notify vendor (queue)
      send confirmation email (queue)
  → if fail:
      release inventory lock
      delete pending order
      show error
```

---

> **یادداشت امنیتی:** هرگز وضعیت پرداخت را صرفاً بر اساس پارامتر callback تعیید نکنید. همیشه با API درگاه پرداخت verify کنید.
